# Local scope and deferred unified validation

Rebuild-046 is the first **local feature freeze candidate**. It is not
compiled, a binary, an equivalent provider service, or a full replacement.
The [124-route decision matrix](LEGACY-ROUTE-BACKLOG.md) separates available
source, deliberately missing routes, and work that requires a supported
protocol and authorization; no legacy route is fully qualified.

## Implemented in source

- Preserve common normalized archive paths, scoped read/write metadata,
  guarded read-only compatibility, bounded projections and read-only
  application setup. All guarded data boundaries remain mode-specific.
- Linux imported media returns a reference descriptor for one exact
  message, including verified digest/size and an explicit Bearer download
  route. The opaque attachment ID is only stable for the same unchanged
  imported bundle, not another path/copy/reimport or a provider identifier.
  Recheck a saved selector; never treat the digest as permission.
- The scoped local source availability endpoint reports whether the
  granted normalized index has rows. It never checks whether a provider,
  credential, raw client installation or internet source is ready.
- On imported-media mode the old media-resolve literal accepts only an
  explicit imported_bundle selector and uses the local verifier. It never
  returns a persistent URL or resolves provider references. The local
  resource-job list uses in-memory exact-grant metadata only.

- Campus dated daily archive view and refresh status use explicit bearer
  roles, ordinary native-live only. They do not implement stock selected
  ranking, remote refresh, automatic feeds, or WebUI parity.
- The desktop mode descriptor reports a redacted subset under existing
  exact-account Bearer and guarded browser-session policies; it does not
  establish an authorized session or choose account permissions.
- The private guarded Linux backup retention CLI reviews an authenticated
  same-account inventory; it never deletes, renames, or schedules backups.

- The provider compatibility registry is compile-target metadata, not a
  probe; listed offline adapters, standalone operator-only IMAP, and local
  alias retirement do not grant or imply live service access. Read the
  [format and protocol triage](PROVIDER-MANIFEST.md) before selecting a
  later provider integration.

## Candidate for one unified local verification pass after approval

1. Restore the exact delivered source/bundle, then compile and run the
   existing pinned/synthetic suites once for this candidate, triaging
   compilation and target-specific failures before application claims.
2. Exercise permissions and mixed-mode denials before parity/benchmark:
   exact/foreign account and plugin, missing/changed archives, harmless
   old alias requests, guard lock/relock, cursor and policy boundaries.
3. Qualify Linux native-lifecycle and receipt/restart semantics, then
   perform independently controlled macOS/Windows builds and supervisor/
   packaging checks with known-good test data. No rare-target inference.
4. Compare the supported stock subsets using the pinned version and
   matched datasets. Include deterministic wire shape, permission and
   settings differences, and performance where equivalent. Per-feature
   benchmarks are not a proxy for all provider/OS behavior.

Still outside this local handoff: operational provider logins and rights,
live/raw platform access, resolved provider IDs, credential acquisition or
storage, network synchronization and remote mutation/sending. Any future
work there requires a separate supported contract and authorization; no
code percentage resolves those questions. No server, connection, fixture,
compiler, test or benchmark has been used for this source checkpoint.
