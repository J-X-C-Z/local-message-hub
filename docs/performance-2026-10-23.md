# 性能优化与 MCP 扩展（2026-10-23）

本轮覆盖本地索引写入、全文索引、搜索分页、批量导入、媒体/统计/设置页加载，以及 MCP 查询入口。保留原有消息、账号隔离、能力开关和发送审批。

## 改动

- 重复消息内容未变化时，不执行 SQLite 更新、全文索引更新及会话聚合扫描；每批按唯一会话创建父记录。正文之外的元数据变化不重建全文索引。
- 搜索先选出所需页，再关联会话及头像信息，避免深页对跳过的记录做关联。新增精确账号和会话条件，分页游标绑定这些条件，保留旧的无范围游标兼容性。
- 文件导入任务预先建立会话 ID 索引，批次只查相关会话；保持原始顺序、重复 ID 的处理及任务恢复位置。
- 媒体、五类统计详情和设置页的独立请求由两轮串行改为一轮并发；请求总数不变，保留功能关闭和切页后旧响应隔离。

## MCP

新增 `list_accounts`、`get_source_status`、`get_import_status`。已有 `search_messages` 新增 `account_id` 和 `conversation_id` 精确范围，可先发现账号再搜索，减少无关消息返回。

`get_source_status` 只返回本地索引计数和当前进程的运行状态，不连接邮箱或探测客户端，不返回配置、凭据、原始错误或文件路径。独立 stdio 进程不能把另一 WebUI 进程的同步状态当作自己的状态。

## 验证与复现

使用标准库测试运行器和仓库 `scripts/check-local-hub.ps1` 完成回归。新增测试覆盖不变消息零写入、正文/空值更新、旧全文索引触发器升级、精确范围游标、恢复导入顺序和前端请求并发。

MCP 使用新子进程验证 `initialize`、`tools/list` 和实际工具调用，数据来自临时合成索引，不是直接调用内部 Python 方法替代协议验收。未新增 HTTP MCP 传输。

合成数据库性能复现：`python scripts/benchmark-store-performance.py --messages 30000 --output <结果.json>`。采用临时 SQLite，包含 60 个会话、每批 500 条；查询取 7 次中位数。旧版与新版结果需要在同一负载环境下比较。

实际邮箱、QQ/微信账号吞吐、真实浏览器内存和生产规模长时间运行未测。本轮不以合成耗时声称真实数据同等加速，也不宣称所有路径都变快。

## 本次测量结果

旧版和新版顺序运行，基准期间完整回归已结束，无其他代理测试任务。基线为修改前 store（仅包含此前已经加入的 email 平台）。每个入库耗时为一轮测量，查询取 7 次中位数；存在机器负载波动，不作为固定服务指标。

| 项目 | 修改前 | 修改后 | 变化 |
|---|---:|---:|---:|
| 首次入库 30,000 条 | 2.550 秒 | 2.180 秒 | 耗时降低约 14.5% |
| 相同 30,000 条重复入库 | 1.959 秒 | 0.254 秒 | 耗时降低约 87.1% |
| 重复入库 SQLite 总变更数（含触发器） | 363,492 | 0 | 不再重写未变化内容 |
| 搜索前 50 条 | 80.53 毫秒 | 41.13 毫秒 | 耗时降低约 48.9% |
| 搜索深页（偏移 15,000） | 109.67 毫秒 | 53.05 毫秒 | 耗时降低约 51.6% |
| 统计查询（未修改实现） | 31.03 毫秒 | 38.45 毫秒 | 本次测量变慢，未计为收益 |
| 10 万会话、200 批导入的会话查找 | 0.576 秒 | 0.097 秒 | 约 5.94 倍；仅查找阶段，含建立索引，不含文件与数据库操作 |
| 媒体/统计详情/设置的请求依赖轮次 | 2 轮 | 1 轮 | 请求数量不变；未测浏览器实际延迟 |

数据源计数在 30,000 条消息、60 会话上 30 次中位数约 1.11 毫秒，未增加缓存机制。

完整仓库检查退出码为 0：914 项 Python 测试、34 项前端检查、5 项源码变更检查、包隐私/清单/启动烟测通过。全文索引升级及父会话恢复边缘情况的最终存储专项共 97 项通过。MCP 50 项测试包含新子进程协议验收。

现有 25,000 条基准也通过：入库 1.704 秒、首次搜索 0.034 秒、50 页遍历 1.859 秒；并发写入与备份恢复验证无失败。此处为修改后单次检查，没有同轮旧版比较。
