# 中大学生信息站

信息站是顶栏中与聊天平台平级的独立入口。进入后切换为信息站自己的侧边栏；返回微信、QQ、邮件等平台时恢复消息档案导航。原有 `#campus` 链接仍然有效，各分栏可通过 `#campus/<section>` 直接打开。

## 信息组织

导航和内容组织参考 [KKKKhazix/AIHOT](https://github.com/KKKKhazix/AIHOT)，研究时固定于 `b3998dc6fc138eb9659f33f55eb38c1c716f0d57`。本项目沿用现有本机运行环境和校园索引，独立实现适合中山大学本科生的处理规则，不使用 AIHOT 名称、Logo 或示范行业数据。

- 精选：启用西湖评分时，DeepSeek 与 GLM 独立评估，二者都认为适用且均分达到70分才入选。未开启模型时使用明确标注的本地规则。
- 全部动态：保留仅标题、仅摘要、日期缺失等条目，明确显示正文可用程度，并可搜索原始内容。
- 热点：先将保守确认的同一事件归组，再按48小时内的独立来源计热度，24小时半衰减。同来源多篇转载不重复增加热度，缺失发布日期的条目不冒充新热点。
- 校园日报：按北京时间的指定发布日期汇总已有材料，保留原始标题、摘录和来源；日期缺失的条目不进入有日期的日报。不将抓取时间当成发布时间，也不把历史日期称作“今天”。
- 主题与收藏：围绕奖学金、竞赛、选课等学生主题浏览，复用已有收藏与已读数据。
- 来源与采集处理：查看真实采集状态、材料完整度和处理数量，启停已接入来源，并调整自动更新。

服务入口和学生资料属于信息站自己的导航。学生资料保存在本机，默认电子与信息学院本科、当前南校园、下一阶段东校园。开启评分后，允许的校区、学院、培养层次、年级与关注词随公开材料发给西湖模型，不发送私人聊天、联系人、邮箱或凭据。

## 采集与处理

采集沿用学校官方公开列表、已选公众号本机缓存、公开文章获取和本机微信网页缓存读取。来源关闭后停止后续采集，已有历史条目、正文、收藏、已读和公众号增量进度继续保留。公众号正文先尝试本机网页缓存，再沿用原有公开HTTP读取；未命中和访问验证不记作全文成功。

处理采用“采集→规范化→材料判断→学生相关性筛选→保守事件归组→热点/日报”的流程。数字年份、届次等关键数字不同的通知不会因标题相似被自动合并。每个事件仍保留原始报道链接和代表文章ID。

西湖评分复用本机 Magpie `http://127.0.0.1:3425/v1`，仅调用精确路由 `westlake-hpc/deepseek-flash` 和 `westlake-hpc/glm-flash`，并校验返回的模型身份；没有其他提供商回退。两次独立评分各保存分数、适用判断、理由、时间和材料依据，取算术平均；任一失败则整对待重试，不用单模型冒充双模型。

仅标题或与标题重复的伪摘要不评分。摘要可评分但明确标注；正文最多发送12000字符，截断时告知模型。公开链接限定中大官网及微信文章，正文视为不可信数据。摘要仍为原文摘录，不由模型补写事实。

结果保存在校园索引的评分表，指纹包含公开材料、允许的学生档案、北京时间日期、两模型和提示版本。内容、档案、日期或提示变化即待重新评分。每批最多5篇，中枢运行时自动续评；失败自动冷却15分钟，手动立即评分可重试。读接口和 MCP 只读缓存，不触发模型请求。暂停模型后恢复本地规则筛选，已有评分不删除。

参考实现的具体设计可见 AIHOT 的 [导航](https://github.com/KKKKhazix/AIHOT/blob/b3998dc6fc138eb9659f33f55eb38c1c716f0d57/apps/web/app/components/shell/nav.ts)、[精选流程](https://github.com/KKKKhazix/AIHOT/blob/b3998dc6fc138eb9659f33f55eb38c1c716f0d57/docs/selection.md)、[采集](https://github.com/KKKKhazix/AIHOT/blob/b3998dc6fc138eb9659f33f55eb38c1c716f0d57/docs/sources.md)和[热点](https://github.com/KKKKhazix/AIHOT/blob/b3998dc6fc138eb9659f33f55eb38c1c716f0d57/packages/backend/src/events/hot.ts)。

## 接口

`GET /api/campus/briefing` 接受 `section=selected|all|hot|daily|topics|bookmarks|sources|pipeline`，以及 `q`、`topic`、`date`、`limit`、`offset`；返回事件、主题、来源状态、材料计数和处理状态。`POST /api/campus/sources/{id}` 接受严格的 `{ "enabled": true或false }`，并持久化启停状态。这些接口都受校园信息能力开关约束。

原有文章查询、全文、收藏、已读、资料、自动更新和公众号导入接口保留。新增只读 MCP `get_campus_briefing` 与网页读取同一处理结果，不会启动抓取或模型调用；已有公众号全文缓存 MCP 工具继续可用。

`GET /api/campus/scoring` 返回双模型评分计数与运行状态；`POST /api/campus/scoring` 接受 `{ "enabled": true或false }`；`POST /api/campus/scoring/run` 接受空对象，启动有界后台批次。三个接口同样受校园能力开关约束。初次安装默认关闭，用户启用后设置持久化。

合并事件通过 `POST /api/campus/events/{representative_id}/state` 设置收藏/已读。服务端重新解析完整事件，并在同一事务中更新所有报道；即使界面只预览前50篇报道，也不会遗漏后面的收藏状态。单篇文章的原有状态接口语义不变。
