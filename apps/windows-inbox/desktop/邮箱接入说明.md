# 邮箱中心

从企微收件台顶部的“邮箱中心”打开。Outlook 与 Gmail 各连接一个账号，可查看收件箱、已发送、分页读取邮件、阅读纯文本正文、写邮件和回复。每页最多 25 封；没有更多分页且未打开弹窗时，每 60 秒刷新一次。读取不会改变邮箱的未读标记。

企业微信接收功能与邮箱模块独立。Codex 中安装邮箱插件不会把插件登录令牌授权给此独立桌面应用；桌面端使用自己的官方 OAuth 应用注册。未配置时会显示“尚未连接”，不会展示假邮件。

未连接时，首页会明确显示“尚未接入收件台”。可点击“打开 Outlook/Gmail 官方邮箱”，在系统浏览器登录后收发邮件；这是官方网页版入口，不代表邮件已同步到收件台。要在收件台窗口内阅读和发送，点击“在收件台内收发：连接账号”，完成下方应用配置和独立授权。没有应用配置或账号授权时，内置收发不可用。

邮箱的授权交换、授权刷新及读取/发送请求统一使用 Electron 独立网络会话，遵循系统网络和代理配置；企微本机消息接口继续使用独立回环通道。不会修改 Windows 的代理设置。读取遇到授权失效时可刷新一次，发送请求仍不自动重放。

## Outlook

1. 在 Microsoft Entra 管理中心的“应用注册”创建应用。使用 Outlook.com 个人邮箱时，账号类型选择支持个人 Microsoft 账号的选项；同时需要组织邮箱时选择支持组织和个人账号。
2. 在“身份验证”添加“移动和桌面应用”平台，配置重定向 URI `http://localhost/oauth/callback`（运行时使用动态端口）；这是本机桌面程序，不使用 Web 应用客户端密钥。
3. 配置 Microsoft Graph **委托权限** `User.Read`、`Mail.Read`、`Mail.Send`，应用通过 `offline_access` 申请刷新授权。组织策略可能要求管理员许可。
4. 复制“应用程序（客户端）ID”，在邮箱中心“邮箱连接设置”填入并保存，点击“登录并授权”，在系统浏览器登录。

官方说明：
- https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app
- https://learn.microsoft.com/en-us/entra/identity-platform/reply-url
- https://learn.microsoft.com/en-us/graph/api/user-list-messages?view=graph-rest-1.0
- https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0

当前使用全球 Microsoft Graph 服务端点，不包含世纪互联运营的 Microsoft 365 中国区专用端点。

## Gmail

1. 在 Google Cloud 项目中启用 Gmail API。
2. 配置 OAuth 同意屏幕；个人测试应用需要将自己的 Gmail 地址加入测试用户。
3. 创建类型为**桌面应用**的 OAuth 客户端并下载 JSON。请勿选择服务账号或 Web 应用。
4. 在邮箱中心切换到 Gmail，打开“邮箱连接设置”，点击“导入 Google OAuth JSON”，然后“登录并授权”。JSON 中的配置只通过本机加密保存，不会显示到聊天或日志。
5. 在系统浏览器完成登录。应用申请 `gmail.readonly` 和 `gmail.send`。Google 测试模式和账号策略可能限制刷新令牌有效期，过期后重新连接。

Gmail 需要完整桌面应用配置中的 `client_id` 和 `client_secret`。只填写 Client ID 时，应用会提示导入完整 JSON，并在打开登录页前阻止这次不完整的授权请求。

官方说明：
- https://developers.google.com/workspace/gmail/api/quickstart/nodejs
- https://developers.google.com/identity/protocols/oauth2/native-app
- https://developers.google.com/workspace/gmail/api/auth/scopes

## 发送与数据

- 填写邮箱地址、主题和正文后，点击“确认并发送”，核对本机确认框中的账号、收件人、抄送、密送和主题，再发送。
- 仅邮件正文发送；当前不提供附件上传/下载、富文本编辑、草稿同步、跨邮箱统一搜索和邮件删除。收到的附件会提示到官方邮箱处理。
- 回复会保留原邮件的 Message-ID 引用；Gmail 另外传递会话 ID。是否聚合到同一会话由邮件服务决定。
- 邮件正文以纯文本呈现，不加载追踪图片，也不执行 HTML 脚本。正文仅在窗口内存中，关闭邮箱窗口后清除；未发送草稿也会清除。
- 账号配置、访问令牌与刷新令牌保存在用户数据目录 `mail-accounts.bin`，使用 Electron safeStorage / Windows 当前用户加密。不会复用或读取 Codex 插件凭据。
- 断开只清除本机令牌；若要撤销服务端许可，请前往 Microsoft/Google 的账号授权管理页面。
- 发送请求不自动重试。网络中断时可能已发送，请先查看“已发送”或官方邮箱，避免重复。Microsoft 的 202 Accepted 表示接受处理，不代表收件人已收到。

## 验证范围

自动测试使用模拟官方 API 响应，验证 MIME 编码、收件人校验、分页边界、OAuth state/PKCE、令牌刷新和发送失败不重放。没有使用真实账号发送测试邮件。真实收件、授权续期和外部投递需要完成上述账号授权后联调。

本轮另外验证未授权首页、官方邮箱按钮、Gmail 配置缺失提示、初始化失败提示，以及注入同一网络通道后从 OAuth 回调、令牌交换到读取邮件列表的完整模拟流程。无窗口的本机网络探测确认 Google/Microsoft 四个端点能经系统代理获得 HTTP 响应；401/405 等未认证响应只说明网络可达，不代表账号授权或真实邮件收发成功。
